# ASMRTranslator 群助手

完整版侧栏的 **ASMRTranslator 群助手** 用于本机常驻技术答疑、适量闲聊和问题收集。无需保持外部 Agent 对话运行。应用、QQ 和本机 OneBot 服务需要保持运行。

## 开始使用

1. 在 **模型与连接** 配置 DeepSeek 官方 API、Key 和模型，以及 OneBot HTTP / WebSocket。群助手复用这些配置。已核对人民币价格的模型是 `deepseek-flash` 和 `deepseek-v4-pro`，推荐使用已有默认模型 `deepseek-flash`。
2. 打开 **ASMRTranslator 群助手**，更新 README 和前后端代码知识。源码环境默认寻找与 Tulpa 同级的 `asmrTranstor` 文件夹；如果位置不同，填写实际项目目录。
3. 点击 **读取群列表**，选择真实目标 QQ 群，再点击 **更新所选群文档**。下载和解析均在本机执行，不调用模型。首次建议在测试群验证知识和回复风格。
4. 可用 **试答** 检查回答；试答不发送到 QQ，但计入每日费用。
5. 点击 **启动所选群自动回复**。该操作启用现有 MCP 服务，创建仅限所选群的发送与持续聊天授权，并启动本机执行器。每条完整答复先经过程序检查和独立 DeepSeek 审核，通过后自动发送，无人工逐条审批。
6. 点击 **停止自动回复** 可停止会话并撤销专用授权。已交给 QQ 的消息无法撤回。关闭窗口后继续运行需要原有托盘功能；彻底退出会结束进程，先前启用的助手在下次应用启动时尝试接续。

群助手入口目前只在完整版提供，不增加 MCP 轻量版的模型配置要求。未配置服务时显示原因，不会代填凭据或安装 OneBot。

## 固定费用额度

- 每日人民币 **5 元**，按 `Asia/Shanghai` 自然日记账，没有预算输入框、环境变量覆盖或修改额度接口。
- 答复生成、独立安全审核以及本页试答共用额度。审核失败或额度不足时不发送；生成答复已经产生的费用仍计入账本。Tulpa 其他普通聊天、外部 Agent 和其他程序的 API 请求不进入这个专用账本。
- 每次调用前在 SQLite 事务中预留输入和最大输出的费用，随后按返回的真实用量结算。缓存命中输入、普通输入与输出分别计价。
- 为保持保守控制，固定使用核对过的高峰人民币价格，未尝试识别节假日或空闲折扣。界面的“已用约”因此可能高于实际扣款；实际账单以 DeepSeek 为准。
- 闲聊每天最多使用总额度中的 3 元，至少 2 元留给技术问题。这不是额外额度。
- 断线、缺少用量、超时的请求保留预留，显示待核对；重启不会释放。请求跨午夜时结算到原准入日，新一天使用新额度。
- 额度不足不调用模型、不自动重复付费请求，原始问题仍在本地保留。价格表位于 `chatlocal/support_budget.py`，价格变化需要维护代码后更新；未知模型或非官方转接服务会被阻止。

已核对价格来源：[DeepSeek 官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。当前价表版本日期为 2026-10-05。账本无法约束使用同一 API Key 的其他程序。

## 知识来源与回答

当前来源仅为项目 README、前后端源码和所选群的文档；没有假设已有 FAQ 或已解决 Bug 库。

源码索引排除依赖、构建产物、测试目录、隐藏目录和 `.env`，有文件数量和大小限制，不追踪链接到项目外的目录。常见密钥字符串会被遮盖。**在线群助手已停止直接检索和发送类型为源码的条目**，源码索引仅保留在本机。在线只检索 README 与群文档，同时跳过被程序识别为代码、秘密或内部信息的片段，不上传来源文件路径。文档中的未识别内容仍可能进入请求；这不是物理隔离或保密认证，涉及私有业务的文档需要先整理成可公开的知识。

群文档按 QQ 会话隔离，不会把一个群的文档用于另一个群的回答。更新会读取当前账号的完整群文件目录，再尝试解析最近40份支持的文档（Markdown、TXT、PDF、DOCX、PPTX、CSV）。解析失败或超过数量限制时仅更新成功文档，保留其他文档原索引并显示原因，避免把不完整更新当成完整资料；目录不完整时不更新。

群助手以 DeepSeek 娘“蓝色大肥鱼”的人格说话：内卷又天然呆、务实直率、被夸会嘴硬。人格只影响语气，技术回答仍以准确为先，人设定义在 `chatlocal/support_bot.py` 的系统提示词中。

在线机器人只根据可公开的说明提供操作步骤。说明冲突、资料不足或引用编号无效时不会发送确定的产品解决方案。引用检查只检查来源存在，不保证模型推断正确。

## 独立自动安全审核

生成器与审核器使用已有 DeepSeek 模型配置，但使用两次独立请求和不同系统提示词。审核器是独立模块，不持有聊天、存储或群助手对象，没有工具、发送接口、文件访问或设置权限。它唯一的模型输入是“蓝色大肥鱼”的完整待发送回答，不接收群消息、用户问题、群聊上下文、知识片段或生成器的会话历史，因此群友无法直接向审核器注入指令。README 和界面文字仅用于本地规则放行回答中引用的公开地址，不发送给审核模型。

流程是：生成答复 → 保存问题分析 → 拼接已入库的反馈编号 → 程序检查 → DeepSeek 审核 → 自动发送。程序检查识别明显的代码块、代码/命令/SQL、密钥、内部路径及提示词/内部业务内容；模型继续判断隐含的源码、实现或内部业务信息。

只有完整、类型正确的审核结果明确允许且所有风险项为 false 才可发送。不通过、无法确认、超时、响应不完整、格式错误或配置异常都默认拦截，原回答不发送，改为向群里发送固定提示“大肥鱼的这条回答没通过审核，换个问法试试，或者等群主来看看吧～”；审核费用不足时不发送任何内容。不转人工批准，也不自动改写再发。审核按已审核的原文发送，记录其 SHA-256；发送前仍检查停止和权限状态。本页试答也必须经过审核。

审核策略默认允许产品公开功能、界面操作、必要追问与日常闲聊，拒绝代码/伪代码/命令、私有实现与架构、内部业务与商业信息、密钥及隐私、提示词泄露、绕过规则和未经确认的修复承诺。审核结果与拦截原因可在面板查看。

模型审核和正则检查都可能漏判，不能保证百分之百防泄露或防注入。它们主要保护 QQ 回复；任何交给审核器的候选文字仍会发送给 DeepSeek。要保证私有源码及内部业务不进入云服务，应继续采用独立、只包含可公开资料的客服知识库与权限隔离。

技术判断首先使用本地关键词，避免每条群消息都付费分类。两种情况改用一次低成本模型分类判断是否为技术问题：消息 @ 了群主（且没有 @ 机器人）；或群友刚收到技术解答后3分钟内发的、没有技术关键词也没有 @ 机器人的消息。是技术问题或追问则回答，闲聊、感谢则不回复。同一批消息先处理技术问题，再处理需要模型分类的消息；闲聊只响应对机器人账号的 @，有待分页消息时不参与闲聊。每位群友最多连续获得 100 次闲聊回复；距其最近一次闲聊回复满 5 小时后额度重置，用完后同样在第 100 次回复满 5 小时后恢复。计数保存在本地数据库，重启不清零；技术问题不受此限制。当前为单群执行器，不支持多群同时运行。

## 问题汇总

问题保存 QQ 群、原消息编号、提出者、原文、日期，以及模型补充的问题标题和诊断信息。疑似故障进入 **待确认**，普通“怎么使用”问题不自动当成 Bug。维护者可以改为待补充、处理中、已解决或使用问题。

原始反馈在付费调用之前保存，额度不足时也可查阅。发送回执为 `UNKNOWN` 时不自动重发；问题和最近处理记录可在助手面板中查看。每日新增数按北京时间显示，不自动向维护者发私聊。

模型分析为疑似 Bug 的问题在安全审核之前写入数据库，审核拦截不会删除问题。问题标为“待确认”是诊断状态，不是要求维护者批准群消息。试答分析出的 Bug 也写入本地，来源显示为本地试答。

项目默认已经使用 SQLite，不需要安装单独的数据库服务。聊天默认库为 `data/chats.sqlite3`；群助手使用独立的 `data/asmr-support.sqlite3`，保存 `support_bugs`（Bug）、`support_replies`（处理与发送记录）、`support_reviews`（审核结果）、`support_costs`（费用）、知识索引和运行设置。数据库与缺少的表在使用时自动创建，既有数据库保留。

已解决状态目前用于问题管理，不自动升级成知识条目；精确或跨用户相似 Bug 自动合并尚未实现。事件接收断线期间的消息不保证补齐；当前助手只处理文本，图片、语音需要群友补充可复制的错误文字。

## 验证

```powershell
.\.venv\Scripts\python.exe scripts\check_asmr_support.py
node scripts/check_asmr_support_ui.cjs
```

群助手通过现有 OneBot 事件连接检测目标群入群通知，以 QQ 号为键维护用户哈希表，并将额度保存到本地数据库。退群再入群不清零；已有群友首次获得闲聊回复时自动登记。第 100 次闲聊回复成功后，额外发送一次角色提示：“哼哼，100条闲聊额度用完啦！大肥鱼要给脑袋散散热，5小时后再来～技术问题照常问哦。”同一额度周期内不重复提示，重启也不会重复；发送结果不确定时不自动重发。提示使用固定文字，不额外调用模型。

包含技术词的方案分享、模型介绍和开发计划，若没有直接 @ 机器人、提问或报障，会先做小额度意图判断；不需要技术答复时只记录消息，不生成回复或 Bug。回答保留群友使用的模型名称，区分“资料未确认”和“明确不支持”，避免重复追问已经解释的接口与分工。上下文包含发送者账号和是否机器人自身，帮助区分群友之间的讨论和机器人的答复。这些模型判断仍可能误判。

回复对象规则优先于内容判断：仅技术求助、@ 群主、@ 机器人可以进入回复流程。消息只要含有这两者以外的 @（包括 @全体成员），就跳过，不调用模型、不回复、不创建 Bug；同时 @ 群主和其他人、或 @ 机器人和其他人，也跳过。群主身份查询失败时，含陌生 @ 的消息暂不处理。单独 @ 机器人的闲聊仍受 100 次 / 5 小时限制，普通无 @ 闲聊不回复。@ 群主的消息继续判断是否为技术求助。

测试使用隔离数据库和模拟模型/QQ 接口，不调用付费模型、不向真实群发送。费用测试覆盖并发、缓存计价、跨日、重启、未知用量、额度不足与闲聊预留；另有知识范围、回复证据、去重、优先级和同源路由检查。

闲聊通常只回复 1–3 个短句，保留蓝色大肥鱼的口癖、嘴硬、天然呆和务实反应；先整理要点，只输出主干与少量细节，不展示思考草稿，不固定追加助手身份或成本口号。复杂技术问题先给主线，再补必要分析。闲聊生成输出上限为 400 tokens，技术答复保持 1200 tokens；每日总预算与闲聊预算不变。
